# اعتبارسنجی مستقل برای Codex Desktop

آخرین نوبتِ کامل گفت‌وگوی باز را با مدلی متفاوت از نویسنده بازبینی کن. افزونه درخواست، تغییرات همان نوبت و شواهد اجرا را کنار هم می‌گذارد و نتیجه را در پنل کنار گفتگو نشان می‌دهد.

- **خلاصهٔ گزارش** — ببین کدام بخش کامل شده، کدام مورد نیاز به پیگیری دارد و کدام ادعا شاهد دارد.
- **شواهد و گزارش کامل** — شاهد هر بند و بخش‌های گزارش کامل را جدا باز و بسته کن.
- **پیگیری در همان گفت‌وگو** — یک یافته را پیگیری کن یا چند مورد منتخب را در یک پیام بفرست. این عمل به پشتیبانی نسخهٔ Desktop از `ui/message` نیاز دارد.

[نمونهٔ گزارش](docs/sample-report.md) · [راهنمای گزارش و محدودهٔ شواهد](docs/report-guide.md) · [تغییرات نسخه](CHANGELOG.md)

## نصب روی ویندوز

۱. Codex Desktop را با حساب خودت باز کن. در PowerShell با `python --version` و `codex --version` بررسی کن که Python ۳٫۱۰ یا جدیدتر و Codex CLI در دسترس باشند.

۲. از صفحهٔ مخزن **Code → Download ZIP** را بزن و ZIP را استخراج کن. PowerShell را در پوشهٔ استخراج‌شده‌ای باز کن که همین `README.md` را دارد. این دو فرمان را اجرا کن.

~~~powershell
codex plugin marketplace add (Get-Location).Path
codex plugin add codex-validator@local-review-tools
~~~

[راهنمای رسمی افزودن منبع محلی](https://developers.openai.com/plugins/build/plugins#add-a-marketplace-from-the-cli)

۳. Codex Desktop را دوباره باز کن. در **Settings → Hooks**، Hookهای **اعتبارسنجی مستقل** را بررسی و تأیید کن. این Hookها رویدادهای مربوط به همان نوبت را ثبت می‌کنند. [راهنمای رسمی Hookها](https://learn.chatgpt.com/docs/hooks#where-codex-looks-for-hooks)

۴. در یک گفت‌وگو در پروژه‌ای محلی، یک کار کوچک انجام بده. پنل **اعتبارسنجی مستقل** را کنار همان گفت‌وگو باز کن، **مدل بازبین** و در صورت نیاز مدل جایگزین را انتخاب و ذخیره کن. سپس **تازه‌سازی** و **اعتبارسنجی** را بزن.

برای نصب از یک مخزن خصوصی، نصب‌کننده ابتدا به مخزن دسترسی می‌گیرد. اگر نسخهٔ پیشین را با Hookهای دستی نصب کرده‌ای، پس از فعال‌کردن Hookهای بسته، ورودی‌های قدیمیِ مربوط به همین افزونه را غیرفعال کن تا رویداد دوبار ثبت نشود.

## عیب‌یابی

| وضعیت | بررسی کن |
| --- | --- |
| پنل بعد از نصب دیده نمی‌شود | `codex plugin list` را اجرا کن و نصب بودن `codex-validator@local-review-tools` را بررسی کن. سپس Desktop را دوباره باز کن. |
| فعالیت جدید ثبت نشده است | در **Settings → Hooks** وضعیت تأیید Hookها را ببین و یک نوبت کامل تازه اجرا کن. |
| گفت‌وگوی قدیمی شواهد کمی دارد | **تازه‌سازی** را بزن. افزونه تا اندازهٔ تاریخچهٔ موجود همان نوبت را بازیابی می‌کند. |
| بازبین اجرا نمی‌شود | مدلی در دسترس انتخاب کن که با مدل نویسنده فرق داشته باشد. در ویندوز فایل اجرایی `codex.exe` باید برای Python قابل یافتن باشد. |
| دکمهٔ ارسال غیرفعال است | علت کنار دکمه نمایش داده می‌شود. بازبینی همان گفت‌وگو باید بارگیری شده باشد و میزبان باید از ارسال مستقیم پشتیبانی کند. |

## داده‌های بازبینی

افزونه شواهد و گزارش‌ها را در پوشهٔ موقت محلی نگه می‌دارد. برای داوری، شواهد مربوط به همان نوبت را از طریق Codex به مدل انتخاب‌شده می‌دهد. [جزئیات دامنه و محدودیت شواهد](docs/report-guide.md)

## ساختار پروژه و آزمون

- `codex-validator/panel.html` و `panel_server.py` رابط و سرور پنل‌اند.
- `codex-validator/validate.py`، `history.py` و `review_items.py` ثبت، بازیابی و داوری شواهد را انجام می‌دهند.
- `codex-validator/hooks/hooks.json` Hookهای بسته را تعریف می‌کند. `.agents/plugins/marketplace.json` افزونه را به Codex معرفی می‌کند.

برای اجرای آزمون‌های محلی Git را در دسترس بگذار و این فرمان را از ریشهٔ مخزن اجرا کن.

~~~powershell
python -B -X utf8 -m unittest discover -s codex-validator -v
~~~

سنجش جداگانهٔ مدل زنده با چهار سناریوی ساختگی و پاسخ معلوم

~~~powershell
python -B -X utf8 codex-validator/benchmark_review.py --model MODEL_ID
~~~

فرمان دوم به دسترسی به مدل انتخابی در Codex نیاز دارد و از سهمیهٔ آن استفاده می‌کند.
